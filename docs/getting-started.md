# Getting Started

## Use the smallest useful message

Copy this template into the engineering channel or tool that already owns the work:

```text
Subject: @Team | Brief description

Priority: Normal | Non-production | Business Hours

Impact: [Optional] What is affected?

Note: [Optional] Supporting technical information.
```

## Three decisions

### 1. What needs attention?

Use a specific, action-oriented Subject. Add the responsible team when it is reasonably known.

```text
Subject: @Mobile | Update authentication header configuration
```

### 2. How urgently does it need a response?

Use the priority that reflects actual impact. Map it to your organisation's severity rules rather than creating a competing scheme.

```text
Priority: Normal | Non-production | Business Hours
```

### 3. What does the recipient need next?

Add Impact and Note only when they improve understanding or action. For urgent work, Impact should normally be explicit.

```text
Impact: QA testing is blocked in staging. Production is unaffected.

Note: Reproduces outside the corporate network. Evidence is attached to the ticket.
```

## Before sending

- Is the Subject specific and free from exaggerated urgency?
- Does Priority match the impact and controlling policy?
- Have you separated confirmed evidence from a hypothesis?
- Is sensitive information kept in the appropriate restricted system?
- Can a recipient understand the next action in one pass?

If yes, send it. Do not delay a material report while trying to make it perfect.
