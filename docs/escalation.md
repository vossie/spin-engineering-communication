# Reporting and Escalation

Reporting and escalation are related but different.

- **Reporting** makes a technical condition visible and gives it an owner and priority.
- **Escalation** changes the response path because impact, risk, or time sensitivity requires it.

A Normal S.P.I.N. report is not an escalation. A Critical report should activate the organisation's existing incident response—it should not attempt to replace it.

## Escalate when evidence supports it

Escalation is appropriate when customer or operational impact is significant, a delivery commitment is materially blocked, risk is increasing, or an expected response has not occurred within the controlling policy.

Avoid using hierarchy, repeated mentions, or emotionally intensified language as a substitute for Impact.

## Controlling systems

S.P.I.N. complements, and never replaces:

- production incident management;
- security incident reporting;
- on-call escalation;
- PagerDuty and xMatters;
- Jira and ServiceNow;
- release management; and
- existing severity classification.

When a policy conflicts with a S.P.I.N. example, follow the policy.
